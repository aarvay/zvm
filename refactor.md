# zvm: pre-release refactor and release plan

**Goal:** a predictable per-user Zig version manager with optional matching ZLS. Breaking changes are intentional; no legacy command aliases or deprecation period. Keep the single Bash executable, explicit `case` dispatch, XDG roots, and Bash/Zsh/Fish completions. No build system, background updater, shell hook, or automatic per-directory switching. Consult `AGENTS.md` for repo conventions; update it to match the finished design. Preserve existing staged/untracked work.

## Public contract (implement and test first)

Selection is **per user**, shared by shells that resolve zvm’s `zig` on PATH. Entering a directory does nothing. An explicit argument overrides `.zvmrc`; only argument-less `install` and `use` read it, from the current directory. With neither, fail with usage. Recommend exact pins. Never source the file as shell code.

| Interface | Behavior |
|---|---|
| `zvm install [SPEC] [--use] [--no-zls]` | Install and reuse verified toolchains. **Never select by default**, even on first install. `--use` selects the exact resolved version after success. Default to compatible ZLS; `--no-zls` skips fetching it, not removing it. Support exact versions and `latest` (stable) / `master` selectors for verifiable builds. No arbitrary SHA or unverified URL fallback. |
| `zvm use [VERSION]` | Select an installed concrete version, offline, without prompting or installing anything. If missing, show the exact `install --use` recovery command. |
| `zvm unset` | Clear selection and owned activation links without deleting installations. |
| `zvm current` | Print only the selected concrete ID; no selection → empty stdout and nonzero status. Report zvm’s selection, not PATH resolution. |
| `zvm list [--remote]` | Local by default, mark selected entry; remote lists builds for this platform, distinguishing stable/dev. Predictable version ordering. |
| `zvm uninstall VERSION` | Remove exactly one inactive managed toolchain. If selected, explain `unset` or switch first. |
| `zvm uninstall --all [--yes]` | Include selected Zig and bundled ZLS. List affected versions and confirm **before changing anything**; without a TTY require `--yes`. Empty set succeeds without prompting. On approval clear selection and remove managed toolchains only. Keep manager, cache, config, project pins and foreign installations. Reject `VERSION` plus `--all`. |
| `zvm zls install [VERSION]` | Add/retry ZLS for installed Zig; default to selected. Idempotent; never switch Zig. No compatible ZLS is informational for ordinary Zig install, an error here. Distinguish unsupported from network/integrity failure; report failures, never activate an unverified payload or stale ZLS. |
| `zvm --version`, `zvm --help` | Manager version only / usage; no dependency checks, writes, cleanup or network. |

Drop `upgrade` (use `install --use latest`), `list-all`, `remove`, `install-zls`, `prune`, `purge` and old spellings. Omit cache maintenance initially; if needed later, use `cache clear` in extended help. Reject unknown flags and excess arguments; avoid implicit prompts. Diagnostics to stderr, data to stdout. Show `zvm install --use latest` as the quick start.

## Implementation priorities

1. **Own paths before mutating them.** Separate requested specs from validated concrete IDs. Validate CLI, `.zvmrc`, current state and remote metadata. Deletion must target a managed non-symlink direct child of the expected root; reject traversal, malformed IDs and unexpected entries. Bulk removal is not a glob over arbitrary contents. Never replace/remove unrelated files or links at `~/.local/bin/{zig,zls}`; check ownership, not just name/type. Diagnose PATH by exact components. Refuse conflicts rather than using force to clobber them.
2. **Isolate and serialize writes.** Current global EXIT trap can delete another process’s extraction and lock even on `help` or failed lock acquisition. Lock all mutations once at the operation boundary; no `cmd_*` calls to other handlers. Require working locking on every supported OS (document dependency or implement tested fallback); never silently skip it. For `flock`, quote the redirection, avoid `eval`, keep the lock inode, close descriptor on exit. Use private per-operation staging and clean up only owned temporaries. Readers must not clean or corrupt shared state.
3. **One verified download path.** `ensure_cached_archive URL SHA256` prints only a verified local path. Require valid trusted upstream digest before extraction **or execution**. Download to `.part`, distinguish interruption from completed corrupt data, discard corrupt downloads, verify then rename. Fetch index once per operation; validate JSON/schema before atomically replacing cache, keeping last good data on failure; respect one-hour TTL. Resolve requested build/platform directly with parameterized `jq --arg`, not interpolated program text or master/latest platform prechecks. Keep Zig/ZLS extraction separate; reject unsafe archive paths/links and unexpected layouts.
4. **Normalize layout and shrink handlers.** Stage the complete distribution on the destination filesystem: `versions/<id>/zig`, its libraries, optional `zls`; validate before publishing. Use `current -> versions/<id>` as authoritative selection instead of a second `current-version` file. No recursive binary search. Keep owned bin links consistent with `current`; an absent ZLS must not expose the previous ZLS. Publish via atomic replacement, preserving prior working selection on failure. For pre-release legacy installs, detect old layout and document reinstall or explicit migration; never silently delete it.
5. **Small Bash contracts.** `ensure_zig_installed` / `ensure_zls_installed` own installation, never selection; `activate_version` is strictly local. Command handlers own policy, prompts and exit codes. Helpers return statuses; explicitly check critical operations (`set -e` is suppressed in conditional function calls). Distinguish absent optional components from failures. Declare `read` destinations local, replace positional policy booleans with focused helpers, use `printf` and TTY-aware colors. Guard `main` with `BASH_SOURCE` and register traps inside execution, not when sourced.

## Verification and delivery order

- Start with CLI acceptance tests under a temporary HOME **and all XDG roots**. Fixture index, fake archives/binaries and stub transport; never touch real user tools. Cover install A → no selection → use A offline → install B leaves A selected → switch → unset → uninstall. Cover project pins, latest resolution once, ZLS absence/failure, `--no-zls`, malformed metadata, traversal, unrelated files/links, spaces, corrupt cache, interruption, and failed activation. Test bulk removal: confirmation decline, noninteractive refusal, `--yes` including active version, repeat on empty, retained non-toolchain files. Run `help` and competing mutations during a paused install. Test shared-cache contention across distinct XDG data roots. Keep deterministic fixtures required on PRs; run a separate, scheduled and pre-release live smoke on Linux and macOS that installs and activates a pinned Zig/ZLS pair and asserts both versions.
- Land safety/lock and verified-download changes, then separate installation from activation, then normalize layout. Run `bash -n`, ShellCheck explicitly on extensionless `zvm`, installer and Bash completion; fix warnings. Test help/completions against the **new** contract. Install Zsh/Fish in CI rather than silently skipping. Replace workflow greps for dependencies in help with actual missing-dependency tests.
- Start with tested Linux and macOS configurations. Enforce/document a precise Bash minimum compatible with chosen features (stock macOS Bash is 3.2); test declared runtime tools, archive formats and utility flags on both OSes. Do not claim FreeBSD/Windows or additional architectures solely because `uname` detection exists. Windows paths/archives and `zig.exe` need end-to-end coverage.

## Open source, distribution and updates

- No root README at review time; MIT `LICENSE`, `install.sh`, workflow files and some docs/tests present but untracked. Confirm owner/repo, license and intended contents before publishing. README: quick start, command/selection contract, `.zvmrc`, prerequisites, supported platforms, PATH/ZLS conflicts, completions, XDG paths, reinstall/migration, updates, rollback and manager removal. Add contribution/testing and security reporting instructions. Update all three completion scripts and their README.
- **GitHub Releases first**, one portable manager script, completion/source bundle with license, SHA-256 manifest and per-tag `install.sh`. Gate publication on successful CI; verify `vX.Y.Z` equals CLI version. Pin workflow actions to reviewed SHAs; least privilege. Handle first release and shallow history (or use generated notes). Existing release workflow advertises `zvm` but uploads no assets: upload to draft, verify actual downloads and installer, then publish. Protect release credentials/tags; enable immutable releases if available, sign checksums or attest artifacts.
- **Replace the current installer**, which fetches mutable `main`, writes over the destination, and edits profiles. Generate a per-release Bash bootstrap embedding the exact tag and SHA-256 of the released `zvm`. Default `${ZVM_INSTALL_DIR:-$HOME/.local/bin}`; no sudo. Download via HTTPS-only curl to `mktemp` in that directory, trap cleanup, verify digest, chmod 755, then rename into place. Refuse foreign/symlink destinations and package-manager prefixes; support replacing an identified bootstrap install. Leave old binary intact on failure. Print PATH advice only; completions opt-in. Test first install, reinstall, upgrade, rollback, bad digest and interrupted download.
- Document `curl -fsSL https://github.com/OWNER/REPO/releases/download/vX.Y.Z/install.sh | bash` **after assets exist**, plus inspect-then-run instructions. Pinned URLs for CI; optional `releases/latest/download/install.sh` for explicit latest stable. Embedded digest binds payload to bootstrap, not independent publisher authentication.
- **Dependency setup:** Keep runtime and tests in Bash with named command-line dependencies, not embedded Python or Perl. Support stock macOS `/bin/bash` (Bash 3.2+) explicitly. Require working file-descriptor `flock` for writes; test the exact syntax on Linux and with Homebrew `flock`. Local `list`, `current`, and completions are read-only and do not require locking. Require `curl`, `jq`, SHA-256 (`sha256sum` or `shasum -a 256`), and BSD tar with XZ for toolchain downloads. Detect a compatible system `tar`; exercise traversal, unsafe links and layout in fixtures. Use stock `mv -h` on macOS and GNU `mv -T` on Linux for checked, same-filesystem symlink replacement. Help/version need no external tools and offline use needs no download tools. The standalone installer fails if it cannot download, verify or safely publish the manager; missing runtime-only tools produce advice without blocking bootstrap. Print one actionable package command where there is a tested mapping (Homebrew on macOS, apt on Debian/Ubuntu). Do not auto-install dependencies, use sudo, bootstrap a package manager, or edit profiles. Native packages should declare dependencies and install completions; Homebrew is the preferred macOS path once the tap exists. Test missing dependencies and clean setup in CI.
- **Completion contract:** Keep token parsing shell-native and use a private, read-only CLI candidate provider for installed, inactive and cached platform-compatible installable IDs. Offer only valid next tokens and never refresh the cache or write on Tab. Assert candidate behavior in all three shells.
- **Update the manager** by rerunning the chosen release installer; roll back with an older tag, documenting state compatibility. Do not alter Zig/ZLS or selection during manager update. Add a Homebrew tap second, using the same versioned release with pinned checksum, dependencies and completions; Homebrew owns its updates. No background update or separate self-updater initially. Zig upgrades remain explicit: `zvm install --use latest`.
